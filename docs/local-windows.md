# Установка CyberGuard AI на Windows 10/11

Инструкция для обычного компьютера с Windows. Docker не нужен: используются Go,
Node.js и локально установленный PostgreSQL. Приложение предназначено для работы
на вашем компьютере (адрес `localhost`). Не открывайте его в интернет без HTTPS и
отдельной проверки безопасности.

Все команды выполняются в PowerShell из папки проекта. Скрипты определяют папку
проекта сами, поэтому диск, имя пользователя и путь (в том числе с пробелами)
могут быть любыми.

## 1. Скачайте проект

1. На странице <https://github.com/kvvor/CyberGuardAI> выберите ветку
   `feature/full-rework`, затем **Code → Download ZIP**.
2. Распакуйте архив в любую папку, например `C:\Users\ВашеИмя\CyberGuardAI`.

## 2. Установите программы

| Программа | Где взять | Проверка в новом окне PowerShell |
|---|---|---|
| Go (версия из `backend\go.mod` или новее) | <https://go.dev/dl/> | `go version` |
| Node.js LTS (вместе с npm) | <https://nodejs.org/> | `node --version` и `npm.cmd --version` |
| PostgreSQL 14 или новее | <https://www.postgresql.org/download/windows/> | служба `postgresql-…` в приложении «Службы» запущена |

При установке PostgreSQL запомните пароль пользователя `postgres`. После установки
программ **откройте новое окно PowerShell**, иначе команды `go` и `node` не будут
найдены.

Используйте `npm.cmd`, а не `npm`: файл `npm.ps1` может быть заблокирован политикой
выполнения PowerShell. Менять системную политику не нужно: в командах ниже
`-ExecutionPolicy Bypass` действует только на один запуск.

## 3. Перейдите в папку проекта

```powershell
Set-Location -LiteralPath 'C:\Users\ВашеИмя\CyberGuardAI'
```

Замените путь на свой.

## 4. Создайте базу данных

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-postgres.ps1
```

Скрипт:

- находит `psql.exe` сам (в PATH, рядом с установленной службой PostgreSQL или в
  стандартной папке установки); если не нашёл — укажите путь параметром
  `-PsqlPath 'X:\...\bin\psql.exe'`;
- спрашивает пароль пользователя `postgres` (ввод скрыт, никуда не сохраняется);
- создаёт роль `cyberguard_app` без повышенных прав и базы `cyberguard` и
  `cyberguard_test`, **если их ещё нет**; существующие базы и пароли не меняет;
- записывает настройки в файл `.env.local` (он исключён из Git) и включает
  регистрацию на сайте для локальной установки.

Если файл `.env.local` уже существует, скрипт ничего не меняет и сообщает об этом.

**Вручную (pgAdmin или своя база).** Создайте базу и пользователя сами, затем
скопируйте `.env.example` в `.env.local` и укажите `DATABASE_URL`, например
`postgres://user:password@localhost:5432/cyberguard?sslmode=disable`. Специальные
символы пароля кодируются для URL (`@` → `%40`, `#` → `%23`). Чтобы регистрироваться
на сайте, укажите `PUBLIC_REGISTRATION_ENABLED=true`.

## 5. Выполните настройку

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

Скрипт проверяет Go, Node.js, npm и службу PostgreSQL, создаёт ключ шифрования
`PROVIDER_MASTER_KEY` (только если его ещё нет), применяет миграции базы данных,
проверяет версию схемы и устанавливает зависимости интерфейса (`npm.cmd ci`).
Его можно запускать повторно: данные не удаляются, базы не пересоздаются, ключ
шифрования не заменяется.

Сохраните резервную копию `.env.local` в надёжном месте. В нём находится
`PROVIDER_MASTER_KEY`: если ключ потерян или изменён, сохранённые API-ключи
нельзя расшифровать — их придётся удалить в настройках и ввести заново.

## 6. Запустите приложение

Нужны два окна PowerShell, оба открыты в папке проекта.

Окно 1 — сервер:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

При каждом запуске сервер сначала применяет недостающие миграции базы данных, затем
стартует. Признак готовности — строка `HTTP server listening`.

Окно 2 — интерфейс:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1
```

Откройте в браузере **<http://localhost:3000>** — именно этот адрес (не
`127.0.0.1:3000`). Остановить каждую программу — `Ctrl+C` в её окне.

Настройки читаются из `.env.local` автоматически при каждом запуске: вводить
`DATABASE_URL` заново не нужно.

## 7. Зарегистрируйтесь и войдите

На странице входа нажмите ссылку регистрации, укажите имя, почту и пароль
(не короче 12 символов), затем войдите. Если регистрация отключена, укажите в
`.env.local` строку `PUBLIC_REGISTRATION_ENABLED=true` и перезапустите сервер.

## 8. Настройте OpenAI

1. Откройте **Settings (Настройки)**, раздел **OpenAI**.
2. Вставьте свой API-ключ OpenAI.
3. Нажмите **«Загрузить доступные модели»** и выберите модель из списка (список
   запрашивается у OpenAI для вашего ключа; можно ввести идентификатор вручную).
4. Нажмите **«Сохранить»**, затем **«Проверить подключение»**.

Проверка подключения только проверяет ключ и доступ к модели: запрос на анализ не
отправляется и ничего не стоит. Сам анализ письма использует вашу квоту OpenAI и
может быть платным. Ключ шифруется на сервере и больше нигде не показывается.

## 9. Настройте VirusTotal

В разделе **VirusTotal** вставьте API-ключ, нажмите **«Сохранить»** и **«Проверить
подключение»**. Проверка запрашивает публичный хеш пустого файла и расходует один
запрос квоты. В VirusTotal отправляются только SHA-256 хеши вложений; файлы никогда
не загружаются. Бесплатный Public API нельзя использовать в коммерческих продуктах
и рабочих процессах организаций — проверьте условия своей лицензии
(см. [virustotal.md](virustotal.md)).

## 10. Проанализируйте первое письмо

1. Откройте **Email Analyzer (Анализ письма)**.
2. Загрузите файл `.eml` или `.msg` (до 10 МБ) либо вставьте текст письма. Исходный
   файл даёт больше данных: заголовки, ссылки, вложения.
3. Отметьте согласие на передачу данных в OpenAI и, если есть вложения, отдельное
   согласие на проверку хешей в VirusTotal. Без согласия на OpenAI вердикта не
   будет — только извлечённые технические данные.
4. Нажмите **«Анализировать письмо»** и дождитесь отчёта (до трёх минут для
   «рассуждающих» моделей).

В отчёте: вердикт, серьёзность, уверенность, объяснение, подтверждающие и
противоречащие данные, заявленные результаты SPF/DKIM/DMARC, репутация вложений,
индикаторы, рекомендации и ограничения. Отчёт сохраняется в **History (История)**;
его можно экспортировать в PDF и JSON.

## После обновления файлов приложения

Остановите сервер, замените файлы, выполните `scripts\setup.ps1` и запустите всё
снова. Файл `.env.local` и база данных сохраняются.

## Ошибки и их устранение

| Что видно | Что делать |
|---|---|
| «The database has not been updated…» / `DATABASE_SCHEMA_OUTDATED`, сервер не запускается с сообщением `database schema check failed` | База не обновлена до текущей версии. Выполните `scripts\setup.ps1` и перезапустите сервер. Данные сохраняются. |
| «The backend did not answer» | Сервер не запущен или упал. Посмотрите окно сервера и запустите `scripts\start-backend.ps1`. |
| `database connection failed` | Служба PostgreSQL не запущена либо в `DATABASE_URL` неверные имя базы, пользователь, пароль или порт. |
| `PROVIDER_MASTER_KEY must contain 32 random bytes` | Выполните `scripts\setup.ps1`. Не меняйте уже действующий ключ. |
| «The saved key cannot be decrypted» | `PROVIDER_MASTER_KEY` изменился. Удалите ключ провайдера в настройках и введите заново. |
| «The frontend origin is not allowed» / ошибка проверки сессии | Откройте сайт по адресу `http://localhost:3000` и обновите страницу. |
| «OpenAI rejected the API key» | Ключ скопирован не полностью, отозван или принадлежит другому проекту. |
| «no remaining quota or credit» | В аккаунте OpenAI закончились средства или квота. |
| «The selected model does not exist…» | Выберите другую модель в настройках. |
| «The model answer did not pass validation» | Ответ модели отброшен проверкой. Повторите анализ или выберите другую модель. |
| VirusTotal: «Not sent yet: request allowance reached» | Исчерпан лимит (по умолчанию 4 запроса в минуту). Через минуту нажмите в отчёте «Проверить оставшиеся хеши». |
| Порт 3000 или 8080 занят | Закройте прежний экземпляр приложения. |
| `npm` не запускается | Используйте `npm.cmd`. |
| Регистрация недоступна | `PUBLIC_REGISTRATION_ENABLED=true` в `.env.local`, затем перезапуск сервера. |

В сообщении о непредвиденной ошибке показывается идентификатор запроса; по нему
в окне сервера можно найти строку журнала с причиной. Ключи и содержимое писем в
журнал не записываются.

Проверить базу данных без запуска сервера:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\backend.ps1 -Mode status
```

## Что проверено, а что нет

Проверено на компьютере разработки (Windows 11): разбор всех скриптов PowerShell,
поиск `psql.exe`, команды `backend.ps1 -Mode status`, запуск сервера и интерфейса,
полный сценарий в браузере с имитацией провайдеров. Не проверено: установка «с нуля»
на отдельном чистом компьютере из ZIP-архива и интерактивный запуск
`setup-postgres.ps1` (он требует ввода пароля администратора PostgreSQL). Реальные
запросы к OpenAI и VirusTotal не выполнялись — см. [rework-checkpoint.md](rework-checkpoint.md).
